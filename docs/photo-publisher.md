# Единый менеджер портфолио через Windows CMD

`publish_photos.cmd` **не изменён**. Он открывает одно Tk-окно с вкладками
**«Новые фото»** и **«Фото на сайте»**. Это не синхронизация локального сайта и не
админ-панель на сервере. Для любых изменений используется свежий Git main,
обычный push, существующий deploy.yml и проверка живого сайта.

## Установка и безопасное обновление

Нужны Windows, Python 3.10+ с Tkinter, Pillow (`python -m pip install Pillow`),
Git for Windows и Node.js 22 в PATH. Для публикации нужны настроенные
`user.name` / `user.email` и право push в `ufaclc-a11y/clc-ufa`. Авторизация —
обычный Git Credential Manager / Git; не добавляйте токены в файлы программы.
Новые пакеты, npm install, Next.js, gh CLI и SSH-доступ к серверу для программы
не нужны. Нужны доступ к GitHub, публичному Actions API, clc-ufa.ru и место для
выбранных оригиналов, подготовленных копий и независимого Git-каталога.

В существующем репозитории читаются его `origin` и имя/почта автора; программа
**не изменяет** его ветку, индекс, файлы, локальные коммиты или worktree. В
отдельной папке используются HTTPS-origin этого проекта и глобальные настройки
Git. Не меняйте origin во время незавершённой операции.

**Не делайте pull, rebase, autostash, reset, clean или push старых локальных
коммитов ради обновления программы. Не копируйте локальный манифест на сервер.**

1. Закройте старое окно. Сделайте резервную копию прежней папки, особенно
   `NewPhoto` со скрытыми `.assignments.json` и `.publisher`, `photo_tags.json`,
   оригиналами, `_published` и локальными изменениями.
2. Распакуйте проверенный архив в новую папку вне Git, например
   `D:\CLC-photo-publisher`. Скопируйте туда **весь** `NewPhoto` и при необходимости
   `photo_tags.json`. Не удаляйте ничего из старой папки. Работайте только в одной
   копии входящих фото.
3. Альтернатива: замените в старой папке **только восемь файлов программы** из
   списка standalone ниже. Не заменяйте `.git`, `data`, `public`, `app`, `NewPhoto`
   или пользовательские JSON. Старые оригиналы и разметку не нужно повторять.
4. При переносе незавершённой пачки сохраняйте всю `.publisher`, включая raw,
   payload и квитанцию. Если прежний origin был SSH, а новая standalone-папка
   использует HTTPS, продолжайте в прежней папке с обновлёнными файлами: смена
   origin блокируется, а не обходится редактированием квитанции.
5. Сначала сопровождающий должен выпустить на сайт новый генератор с полным
   индексом. До появления корректного `/portfolio-index.json` программа намеренно
   не подтверждает публикацию/удаление. Не удаляйте квитанцию для обхода проверки.

Проверка установки без публикации:

```cmd
python -c "import tkinter; from PIL import Image, ImageTk; print('Python / Tk / Pillow OK')"
git --version
node --version
```

## Вкладка «Новые фото»

1. Положите оригиналы в `NewPhoto`, запустите CMD и отметьте категории, как раньше.
   Можно выбрать несколько. Фото без категории остаются на месте.
2. Нажмите «Опубликовать». **Пачки из 65 и более фото в одной категории не нужно
   делить вручную.** Лимита 48 у проверки больше нет; HTML страницы категории
   остаётся превью и не используется как полный список.
3. Имена, все исходные теги, категории, хеши и копии выбранных оригиналов
   замораживаются в `NewPhoto/.publisher`. Незнакомый тег не теряется: он
   останавливает новую публикацию с пояснением. Снятие пользовательской галочки
   не стирает неизвестные старые теги; удаление дополнительного checkbox не
   удаляет сохранённые теги оригиналов.
4. В свежую независимую копию main добавляются только выбранные изображения и
   недостающие связи. Чужие записи, метаданные и порядок не заменяются. Известные
   журналу удаления связей нельзя отменить устаревшей загрузкой с другого ПК:
   требуется явное восстановление через журнал.
5. Только после успешного точного workflow и проверки полного индекса и байтов
   выбранных изображений неизменённые оригиналы архивируются в `_published`.
   Исходные теги остаются в квитанции; снимается лишь совпадающая входящая разметка
   завершённой пачки. Неизменённые чужие записи разметки остаются на месте.

Старые незавершённые квитанции **v1** поддерживаются. Пока есть незавершённая
пачка, новые фото не добавляются в неё. После ошибки нажмите ту же кнопку повтора,
даже если прерванная архивация уже убрала исходники из видимого списка.

## Вкладка «Фото на сайте»

1. Нажмите **«Свежий каталог main»**. Читается удалённый Git main, а не старый
   локальный манифест. Вверху показан SHA. Надпись «Живой сайт соответствует main»
   появляется только при точном совпадении полного публичного индекса, включая
   порядок и хеши. Иначе явно показано: main прочитан, сайт отличается / ещё не
   подтверждён. Ошибка обновления не выдаёт старый список за текущий.
2. Ищите по имени файла / подписи, фильтруйте по категории. На странице списка
   не более 12 фото. Миниатюры загружаются лениво только для этой страницы,
   последовательно, с лимитом размера/времени; в памяти не более 24 миниатюр.
   Несовпадающие с main байты живого фото не показываются как его миниатюра.
3. Выделяйте несколько строк через Ctrl / Shift, используйте «Выбрать все
   найденные» и «Снять выбор». Выбор сохраняется между страницами и фильтрами:
   смотрите общий счётчик. Окончательное подтверждение перечислит **все** файлы,
   в том числе скрытые фильтром.
4. **«Изменить категории…»** заменяет набор категорий каждого выбранного фото
   явно выбранным набором. Общие категории первоначально отмечены; разные
   категории не считаются автоматически общими. Сохраняется порядок оставленных
   связей и прочая метаинформация. Новые связи получают порядок перед текущими.
5. **«Убрать из категории фильтра…»** удаляет только эту связь у выбранных фото;
   остальные категории сохраняются. Если это была последняя связь, запись
   исчезает из портфолио, но файл остаётся.
6. **«Убрать из всего портфолио…»** удаляет записи выбранных фото из манифеста.
7. Перед любым эффектом открывается прокручиваемое подтверждение: все имена,
   категории ДО → ПОСЛЕ, количество и предупреждение об оставшихся URL.
   По умолчанию выбран безопасный выход «Отмена». До явного «Подтвердить» нет
   квитанции новой операции, commit или push.
8. **«Журнал / восстановить…»** показывает действия из свежего main, доступные
   и на другом ПК. Выберите действие и восстановите состояние **до него**.
   Это обратное изменение только его фото, не замена всего манифеста старой
   копией. Возвращаются исходные категории, порядок и дополнительные поля.
   Если те же фото позже менялись, возврат останавливается с конфликтом.
   Изменения других фото не мешают и не теряются. Возврат сам записывается в журнал.

**Удаление из портфолио не является удалением конфиденциальных данных.** Физические
изображения намеренно сохраняются: их могут использовать другие страницы,
обложки или hero. Прямой `/images/portfolio/<имя>` может остаться доступным.
Оригиналы в NewPhoto / `_published` также не удаляются операциями этой вкладки.
Для удаления самого файла/приватного материала требуется отдельная проверка всех
ссылок и отдельная процедура, не эта кнопка.

## Повтор, конфликт и восстановление после сбоя

У загрузок и правки/удаления/возврата общая `.publisher/active.json`: новая
операция не заменяет незавершённую. Правки используют квитанцию v2 с уникальным
ID и точными целевыми снимками. SHA кандидата записывается **до push**, принятый
SHA — после. При потерянном ответе Git проверяется ancestry кандидата в свежем
main; повтор не создаёт второе удаление или второй журнал.

Push повторяется не более трёх раз без force. Перед каждой попыткой берётся
свежий main. На тех же целевых фото проверяется весь снимок метаданных, хеш файла
и последнее действие журнала (включая удаление → возврат с тем же содержимым).
Изменение чужой цели не затирается. Независимые действия и поля журнала сохраняются.

После принятия main программа ждёт **deploy.yml, event push, branch main и точный
SHA** (до 20 минут, опрос не чаще раза в 30 секунд), затем сравнивает полный
`/portfolio-index.json` со свежей основой операции и SHA-256 прямых выбранных
изображений. Один HTTP 200, зелёный чужой workflow, имя файла в скрипте/hero или
первые 48 `<img>` не подтверждают завершение. Если main за это время обновился,
индекс может ещё не совпадать: квитанция сохраняется, повторите проверку позднее.

При ошибке API, deploy, индекса или изображений **не удаляйте `.publisher`**.
Кнопка внизу продолжит ту же загрузку / изменение / возврат. Push мог уже пройти.
Ошибки оставляют оригиналы и входящие теги; во время работы мутации UI отключены.
Обычное закрытие занятого окна блокируется; после аварии остаётся квитанция.

При конфликте цели **до принятого push** можно нажать
**«Отменить непринятое изменение (проверка main)…»**. Программа заново проверит
main, ancestry и журнал. Только доказанно непринятая правка архивируется локально
в `.publisher/cancelled`, не удаляя квитанцию или входящие фото. Затем обновите
каталог и выберите действие заново. Уже принятую операцию или v1-пачку эта кнопка
не отменяет. Если принятое действие позже изменили/удалили на main, программа
не восстанавливает его молча; сохраните квитанцию для разбора сопровождающим.

Удалённый журнал `data/portfolio-history.json` — append-only история целевых
изменений (полные before/after, хеши, ID предыдущих действий, связь undo).
Удалённые связи оставляют tombstone и блокируют их тихое воскрешение старой
входящей пачкой. Не редактируйте историю вручную для обхода конфликта.

## Технические границы

- Независимые временные репозитории используют blob-filter и sparse checkout
  только замыкания портфолио/генератора. Не распаковываются огромные tracked
  screenshots / видео. Полная история коммитов остаётся для ancestry; depth=1
  не используется. Локальный Git-сервер может не поддерживать blob-filter,
  но sparse checkout всё равно ограничивает рабочие файлы. Нужны место и сеть
  для самих портфолио-фото и Git-истории. Temp берётся через `tempfile` / Windows TEMP.
- Разрешённый commit: новые фото выбранной пачки, `data/portfolio-tags.json`,
  `data/portfolio.generated.ts`; у правок дополнительно только
  `data/portfolio-history.json`. Физические фото не удаляются.
- Генератор строит TypeScript и публичный индекс из **одного полного mapping**.
  Индекс содержит только имена, категории и SHA-256, без подписей, приватной
  метаинформации, истории, тегов входящих оригиналов или credentials. JSON —
  runtime-derived output в `.gitignore`, создаётся `predev`/`prebuild` в public,
  не добавляется в фото-коммиты. Отсутствующее изображение прерывает генерацию.
- Нет нового Next API, route, admin или auth-поверхности.
- Stdlib HTTP работает в короткоживущем принадлежащем запросу Python-процессе.
  Абсолютный срок охватывает DNS, connect/TLS, заголовки и тело; по истечении
  процесс kill/reap, каналы закрываются. Запуск/IPC входят в бюджет. Задержки
  планировщика, ОС и антивируса не являются гарантией реального времени.
- ОС-блокировка не допускает два окна с одним NewPhoto и освобождается после
  выхода/аварии. Не удаляйте `.publisher.lock` и не редактируйте NewPhoto другой
  программой в процессе операции. На разных ПК конкуренцию контролируют CAS,
  журнал и обычный non-fast-forward push, а не локальная блокировка.
- При изменившемся оригинале, конфликте содержимого под тем же именем или
  невозможности сохранить квитанцию работа останавливается. При обычной ошибке
  завершения архивации возвращаются уже убранные оригиналы и разметка. Это не
  многофайловая транзакция при отказе диска/питания: проверяйте raw, payload,
  `_published` и квитанцию, не стирайте резервные копии.

## Состав standalone-архива

Из одного проверенного кандидата берутся **только**:

```text
publish_photos.cmd
publish_photos.py
safe_photo_publisher.py
portfolio_manager.py
portfolio_manager_ui.py
portfolio_maps.py
photo_tagger.py
docs/photo-publisher.md
```

`photo_tagger.py` нужен для общего списка тегов; отдельно запускать его не нужно.
Фото, пользовательские JSON, `.publisher`, `.git`, npm-зависимости, ключи,
токены и `.env*` в архив не включаются. Переносите свои данные отдельно из копии.

## Проверки и граница доказательства

```text
python -W error::ResourceWarning -m unittest discover -s tests -p "test_safe_publisher.py" -v
python -W error::ResourceWarning -m unittest discover -s tests -p "test_portfolio_manager.py" -v
node --import tsx --test tests/portfolio-index.test.ts
```

Первые две команды используют только stdlib, Git, Node и loopback HTTP;
они включены в CI до npm ci. Исполняются реальные GUI workers headless через AST,
локальные bare Git-публикации, потерянный ACK после настоящего локального push,
конфликты/гонки журнала, точный workflow, полная проверка и архивация 65 фото одной
категории. Node-тест проверяет full-index ↔ TS parity, отсутствие устаревших членов,
исключение приватных полей и отказ при отсутствующих assets.

Дополнительно, с Tk/Pillow и DISPLAY (например Xvfb):

```text
python -W error::ResourceWarning -m unittest discover -s tests -p "test_portfolio_tk.py" -v
```

Эта необязательная графическая проверка исполняет реальные вкладки, фильтры,
множественный выбор, ограниченные миниатюры, busy-состояния и прокручиваемое
подтверждение. Без графической среды она явно SKIP, не доказательство GUI.

**Linux/offline-проверки не заменяют Windows:** двойной клик CMD, реальные
Tk-диалоги, Pillow (JPEG/EXIF/прозрачный PNG/WebP), Git Credential Manager / SSH,
PATH, Unicode/длинные пути, msvcrt, антивирус, блокировки файлов, перенос архива
и дочерний Python должны быть проверены на целевой машине. Полные web-gates,
независимое ревью, выпуск и read-only live acceptance выполняет сопровождающий.
Никаких настоящих удалений/возвратов на production для тестов не требуется.

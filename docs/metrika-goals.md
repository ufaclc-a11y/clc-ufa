# Цели Яндекс.Метрики (счётчик 53776969)

Памятка по событиям-конверсиям, которые отправляет сайт. Чтобы конверсия
считалась, в Метрике должна быть создана цель типа **«Целевое событие · ex
JS-событие»** с идентификатором, **точно совпадающим** со строкой из колонки
«Идентификатор».

> Счётчик загружается при первом монтировании
> [`components/CookieConsent.tsx`](../components/CookieConsent.tsx)
> **независимо от баннера** — `loadMetrika()` вызывается до проверки согласия.
> Баннер информационный: он ссылается на `/privacy` и закрывается.
> Для проверки целей принимать его не нужно.
>
> Скрипт приезжает асинхронно, поэтому `trackGoal()` вызывает `window.ym`
> через optional chaining: событие в первые мгновения после загрузки страницы
> может не уйти.

Все события шлются через хелпер `trackGoal()` из
[`lib/analytics.ts`](../lib/analytics.ts):

```ts
ym(53776969, 'reachGoal', '<идентификатор>', { ...params })
```

## Созданные цели (лиды и интерес)

| Идентификатор | Когда срабатывает | Где в коде |
|---|---|---|
| `order_email` | Заявка с формы расчёта успешно доставлена (API `/api/send-email` вернул ok) | `components/OrderForm.tsx` |
| `order_whatsapp` | Заполнил форму расчёта и отправил в WhatsApp | `components/OrderForm.tsx` |
| `order_telegram` | …отправил в Telegram | `components/OrderForm.tsx` |
| `order_max` | …отправил в MAX | `components/OrderForm.tsx` |
| `cta_calculator` | Клик по кнопке «Рассчитать стоимость» | `components/ContactButtons.tsx` |
| `js_error` | Непойманная ошибка на странице (не конверсия — мониторинг) | `app/error.tsx`, `app/global-error.tsx` |

## Магазин — воронка покупки

Эти цели **нужно создать в Метрике вручную**, иначе события уйдут в пустоту:
идентификатор в панели должен совпадать со строкой ниже посимвольно.

| Идентификатор | Когда срабатывает | Где в коде | Параметры |
|---|---|---|---|
| `add_to_cart` | Товар добавлен в корзину | `lib/cart.tsx` | `id` — id товара |
| `begin_checkout` | Отправлена форма оформления заказа | `app/shop/checkout/CheckoutClient.tsx` | `count`, `total` |
| `order_submit` | Заказ принят сервером (API `/api/order` вернул ok) | `app/shop/checkout/CheckoutClient.tsx` | `order` — номер, `total` — сумма |

Ключевая конверсия — `order_submit`: `begin_checkout` срабатывает при отправке
формы и до ответа сервера, поэтому включает неудачные попытки. Разница между
ними показывает, сколько заказов теряется на ошибках валидации или отправки.

Оплата на сайте не принимается, поэтому цели «покупка» нет: `order_submit`
означает принятую заявку на заказ, а не поступление денег.

Рекомендуется отметить `order_email`, `order_whatsapp`, `order_telegram`,
`order_max` как **ключевые цели** — Директ использует их для автостратегий.

## Шлются кодом, но цели не создавать (дубль автоцелей Метрики)

Эти события сайт отправляет из `components/ContactButtons.tsx`, но в Метрике
их уже покрывают **автоцели** (клик по телефону, мессенджеру, соцсети), поэтому
отдельные цели заводить не нужно — иначе будет двойной учёт.

| Идентификатор | Покрывающая автоцель |
|---|---|
| `contact_phone` | «Клик по номеру телефона» |
| `contact_whatsapp` | «Написал в ватсап» |
| `contact_telegram` | «Написал в телеграм» |
| `contact_max` | «Переход в MAX» |

## Как добавить новое событие

1. Вызвать `trackGoal('my_goal', { ...опц. параметры })` в нужном месте
   (импорт: `import { trackGoal } from '@/lib/analytics'`).
2. В Метрике создать цель «Целевое событие» с идентификатором `my_goal`.
3. Добавить строку в таблицу выше.

## Проверка

1. Открыть сайт, **принять cookie-баннер**.
2. Совершить действие (отправить форму / кликнуть CTA).
3. Network в DevTools → фильтр `mc.yandex` → запрос с нужным `goal`,
   либо Метрика → «Отчёты → Конверсии» / режим «В реальном времени».

Цели считаются **с момента создания** в Метрике, задним числом не
пересчитываются.
